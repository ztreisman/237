## Summary of work since last journal entry

### Physics relaxer breakthroughs

**hyperbolic_triangle_gnn.py** was debugged extensively on lambda01:
- Root cause of slowness: `CRYSTAL_ALIGN=0.02` and `CRYSTAL_SNAP=0.01` caused `crystal_snap_forces()` to run every step → 9.9s/sample. Fixed: both set to 0.0.
- `has_collision()` was O(62k pairs) in pure Python Möller–Trumbore loop → ~45s/sample. Fixed: fully vectorized batch ray-triangle test + precomputed pair cache keyed by (F, max_ring). Now ~25ms/call.
- `rebuild_rep()` had Python loop over query_pairs output. Fixed: boolean adj_mat vectorized lookup.
- `RELAX_STEPS` set to 10000 (simultaneous, full mesh) to reach edge_std ~0.02, matching Rust quality.
- GNN search loop: added physics fallback after L0 retries exhausted, quality threshold (edge_std>0.15 rejected).
- Best GNN result: ring 4 with edge_std=0.197 (physics fallback).
- Physics training data: edge_std as low as 0.0077 on ring 4.

### physics_grow.py — standalone physics-only grower

New file `physics_grow.py` grows the mesh ring by ring using pure physics:
- Builds combinatorial structure **incrementally** (one ring at a time) — avoids building 76k-vertex matrix upfront.
- Warm-starts new ring vertices at **centroid of existing neighbors** — prevents NaN explosion.
- Relaxes **full mesh simultaneously** (all rings free) after each ring addition — matches Rust approach.
- **Convergence criterion** replaces fixed step count: stops when edge_std improves <1e-5 over 500 steps.
- **Best result: ring 5 (617 vertices, edge_std=0.047)** across 20 seeds with re-relax.
- Ring 6 (1625 vertices) consistently collides — may be geometric limit or need more convergence time.
- Ring 4 achieves edge_std=0.001–0.005 (near perfect equilateral).
- Files saved as `physics_grow_seed{N:02d}_ring{r:02d}_std{s:.4f}.ply` with viridis ring coloring.

### vZome disk coloring work

**Lattice naming convention (established):**
- J_0 = icosahedron centered at origin (old I_0)
- I_0 = neighbor across O_0 from J_0 (the "anchor" neighbor)
- I_x, I_y, I_z = neighbors across O_x, O_y, O_z respectively
- Red ball = vertex of J_0 on the O_0 face: coordinate `"0 0 2 3 1 2"` = (0, φ⁴, φ³)

**color_disk.py** — tool to apply any palette to the {3,7} disk in a vZome file:

    Usage: python color_disk.py <input.vZome> <palette_name> [output.vZome]

    Available palettes: viridis, zissou, zissou_cont, grandbudapest1, grandbudapest2,
    moonrise1, moonrise2, moonrise3, darjeeling1, darjeeling2, fantasyfox,
    cavalcanti, royal1, royal2, chevalier, rushmore, asteroidcity1, asteroidcity2,
    bottlerocket, isleofdogs1

    To change the disk center, edit line 102:
        red_ball = "0 0 2 3 1 2"
    Replace with any Z[φ]³ coordinate string from the file.

**Z[φ]³ coordinate format:**
Coordinates are stored as 6 integers: `"a b c d e f"` representing
    (a + b·φ,  c + d·φ,  e + f·φ)
where φ = (1+√5)/2 ≈ 1.618.
Example: `"0 0 2 3 1 2"` = (0+0φ, 2+3φ, 1+2φ) = (0, φ⁴, φ³) ≈ (0, 6.854, 4.236).
Useful values: φ³=1+2φ≈4.236, φ⁴=2+3φ≈6.854, φ⁵=3+5φ≈11.09, φ⁶=5+8φ≈17.944.
To find coordinates: open the vZome file as text and search for `<SelectManifestation point="...">`.

**Extended disk files** (disk_extended_{palette}.vZome):
- 691 balls, rings 0–17, generated from lattice_unit_colored.vZome
- Generated by applying translation vectors T8=(φ³, 8+13φ, -φ⁵) and T10=(-7-11φ, φ⁶, -φ⁴)
  to the base unit cell at combinations n8,n10 ∈ {-3..3}.
- Note: ring numbers are graph-distance in the *crystal* graph (ico+oct edges),
  not pure {3,7} combinatorial distance. Rings wrap the crystal structure.
- New balls added via LoadVEF; struts may need manual connection in vZome.
